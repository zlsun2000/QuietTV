# UI / UX 升级验收记录

本文面向开发与测试人员，记录 v1.0.0 任务二的界面基线和验收目标。设备测试使用独立的可丢弃模拟器，截图和性能数据保存在不进入 Git 的 `emulator-local/`；模拟器结果不代表电视实机。

| 项目 | 改动前基线 | 可测目标 |
| --- | --- | --- |
| 续播卡片 | 标题在卡片下方，来源和动作叠在海报上；无图使用本地底色 | 无图、长中英文标题、已知/未知进度及不同动作均可辨认；焦点说明保留完整名称；不增加数据或改变续播动作 |
| 焦点与导航 | 卡片有焦点放大和轮廓，设置项反色；任务一的性能归因未确定 | 颜色和轮廓在浅、深背景可辨；遥控首尾、返回和整行裁切仍可用；未获性能证据前不改焦点动画 |
| 整理 | 长按菜单可管理应用，分类通过设置整理 | 用户能找到长按和整理入口；隐藏、移动后的焦点可预测；恢复路径明确 |
| 空状态 | 空常用应用仅显示说明，空续播不显示行 | 关闭续播时隐藏整行；开启后按已有权限和记录状态说明，可用遥控器到达下一步 |
| 背景可读性 | 主页文字直接位于用户选择的图片或视频之上 | 浅、深背景下标题及焦点可辨；不做逐帧采样或实时模糊，不改变壁纸生命周期 |
| 控制中心 | 主页有输入源、电视设置和桌面设置三个工具，桌面设置为右侧文字面板 | 中心包含时间、网络、信号源、系统设置和个性化入口；设置有五组和主页布局，支持逐级返回、焦点恢复和大字号；不增加重复工具栏入口 |

性能比较需在相同设备、内容和遥控输入下记录前后帧耗时与内存。此前 API 34 电视模拟器采用软件图形渲染，基线 249 帧均超时，不能据此推断 Google TV Streamer 的主要瓶颈。TCL Android 9、Google TV Streamer 及真实低内存路径的结果必须单独记录，未运行时标为未验证。

## 首轮候选验证（2026-11-11）

- 改动前的设置、整理、空常用与三条合成续播截图，及浅/深背景对比，保存在 `emulator-local/uiux-baseline-20261111/`。截图使用单独创建的 API 34 Android TV 模拟器和临时测试签名；不是电视实拍。
- 集成候选编译和 406 项核心检查通过。模拟器设置检查 108 项、显示检查 198 项通过，覆盖控制中心返回焦点、两列大字号、输入设置、布局开关、空状态、整理、续播说明与视频恢复。浅色与深色图片截图显示标题和卡片文字可辨；1.6 倍字号截图显示控制中心入口和主页日期完整。
- 在一次设置补测中，模拟器处理安装保护提示后进入触摸模式，输入源页面未获得焦点。为设置控件增加触摸模式下的可聚焦性，并限制延迟恢复不覆盖用户后续选择；修复后以真实方向键启动的原设置检查通过 108 项。正式回归在 Activity 启动后注入真实触摸，确认输入源页面处于触摸模式且首项获得焦点，整套通过 110 项。后续方向键会使模式变化，不能把整套测试说成始终处于触摸模式。
- 用同一临时测试签名从 versionCode 39 的基线 APK 实际覆盖安装 versionCode 40 测试 APK 后，界面仍可见原有常用应用和三条合成续播记录。这不等于官方签名 APK 升级验证，也不证明全部偏好已逐项比较。另有全新安装 31 项、模拟旧配置后覆盖同一 APK 的升级检查 12 项通过。
- 未连接 TCL Android 9 或 Google TV Streamer；没有验证 `isLowRamDevice=true`。任务一的滑动根因尚未确定，原有焦点缩放和滚动行为保持不变。控制中心预绘制和淡入淡出的性能收益尚未在真实设备验证。

## 双栏控制中心和主页布局复测（1.0.0，versionCode 41）

- 编译与 406 项核心检查通过。
- 隔离的 API 34 TV 模拟器通过 166 项设置、208 项显示、31 项全新安装和 12 项旧配置升级检查。验证了分行后关闭续播会隐藏标题和提示，重新开启会恢复保存的卡片。隐藏主页输入源会移除主页行和常用应用中的输入源快捷入口，控制中心仍可选到输入源。大字号、逐级返回和四个开关的持久化也通过检查。
- 仅在本地测试构建中强制启动器采用低内存分支，API 34 TV 模拟器通过 170 项设置检查。控制中心跳过预绘制和过渡动画，方向键与返回操作可达。
- TCL Smart TV Pro（Android 12）用原签名覆盖安装，核对了已安装 APK 的摘要和原有应用数据目录。通过 ADB 方向键检查右上角 Wi-Fi 状态、四个开关、输入源页和返回焦点。桌面与控制中心截图保存在本地。TCL Android 9、Google TV Streamer 和真实低内存设备尚未实测。

## 同场景性能对照

在同一 API 34 模拟器、同一临时签名下，使用 `tests/device/performance/` 的合成夹具，分别运行旧版和首轮候选版各一次：42 个合成应用、3 个常用应用、1 条合成续播记录，发送相同的 54 次遥控输入；两次焦点类别序列一致。模拟器为 1920×1080、320 dpi，系统报告非低内存，使用 SwiftShader 软件图形渲染。

| 指标 | 旧版 | 候选版 |
| --- | ---: | ---: |
| 记录帧数 | 568 | 567 |
| 帧耗时 P50 / P95 | 32 / 46 ms | 30 / 46 ms |
| 系统标记的卡顿帧 | 72（12.68%） | 64（11.29%） |
| 应用进程 PSS，开始 / 结束 | 41,626 / 46,457 KB | 45,776 / 49,577 KB |

每版仅一轮，软件渲染和运行波动均可能影响结果，不能据此认定性能改善或代表真实电视；候选版的两次 PSS 采样分别高 4,150 / 3,120 KB，需要多轮及真机复核。该场景比较首页导航，不测量控制中心首开耗时；采样后候选版还修改了设置控件在触摸模式下的焦点恢复，未重新采集性能。原始结果保存在不进入 Git 的 `emulator-local/performance-old-20261111-02/` 和 `emulator-local/performance-new-20261111-02/`。
