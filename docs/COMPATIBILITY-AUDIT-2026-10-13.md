**QuietTV 全功能与跨品牌兼容性复审清单**

审查日期：2026-10-13。基线：本地提交 `61b58c8`，0.13.0 / versionCode 21。覆盖全部 launcher Java 类、manifest、资源配置、安装/恢复脚本、核心检查、设备检查及公开项目文档。下方 P1/P2 是审计时发现的问题与建议；文末记录随后在本地源码完成的优化。优化尚未发布，也没有本轮真实电视验证。

结论：基础桌面已经具备通用设计，但现有证据不足以承诺全品牌兼容。建议以“基础桌面稳定、可选能力有检测与回退、每项能力独立标注验证结果”为发布标准。品牌不是适配单位；同一品牌不同地区、型号、系统及固件应分别记录。

本次实测：在隔离源码副本中，以 JDK 17、Platform 28、Build Tools 34.0.0 执行 Windows 干净构建、APK 签名验证和 `tests/run-core.ps1`，**148 项核心检查通过**。使用独立临时测试签名。最初系统临时目录中的检查遇到 Java 文件访问限制，改在工作区隔离副本后，原构建与检查脚本正常通过。未运行模拟器，未查看线上 workflow 结果，未连接、发按键、播放、截图或重启任何电视。

**支持范围应这样划分**

| 层级 | 应交付的行为 | 边界 |
| --- | --- | --- |
| 基础桌面 | 应用启动、收藏/分类/排序/隐藏、遥控器导航、静态背景、时间；离线及拒绝可选权限仍可用 | 面向允许安装 APK 的 Android 6.0+ 电视/盒子；需要实际固件验证 |
| HOME 集成 | 用户明确设置默认 HOME、检查状态、可恢复原桌面 | 安装成功、按 Home 返回、冷启动进入、休眠唤醒应分四项；OEM 策略可能限制 |
| 可选增强 | HDMI/AV、动态背景、天气、播放记录、Home 键过滤 | 每项按可用能力开放，失败仍保留基础桌面 |
| 范围外 | 非 Android 系统、禁止第三方安装的固件 | 当前 APK 无法解决；外接兼容 Android 盒子是另一台设备的适配，不能算电视本体兼容 |

无需为 ARM/x86 各维护一套 Java 业务代码；项目没有 JNI。不过实际性能、平台解码器和固件行为仍要测试。不能用“Android 版本满足最低要求”替代整机验收。

**优先级与证据说明**

P1：建议下次兼容性版本优先解决。P2：完善日常体验和长时间稳定性。P3：后续扩展。这里是优化排序，不等同于安全漏洞严重等级。“已确认”表示源码路径或测试内容可直接确认；“待测”表示存在实现缺口或平台差异，尚未复现具体设备故障。

现代系统迁移的准确边界：包可见性过滤针对 target 30+，因此不能把当前 target 28 的所有查找失败都归因于包可见性。[包可见性](https://developer.android.com/training/package-visibility)。提高 target 后还需处理作用域存储与动态 receiver 标志。[Android 11 存储](https://developer.android.com/about/versions/11/privacy/storage)、[Android 14 receiver 要求](https://developer.android.com/about/versions/14/behavior-changes-14#runtime-receivers-exported)。Android 15 的低 target 安装门槛是 24，当前 28 高于此门槛；这不证明所有新电视均能安装，也不能代替未来版本检查。[Android 15 安装限制](https://developer.android.com/about/versions/15/behavior-changes-all#minimum-target-api-level)。

标准 TV Input Framework 对硬件访问有系统权限边界，第三方桌面应复用实际公开输入与播放入口，不能承诺自行控制所有 HDMI/调谐器。[AOSP TV Input Framework](https://source.android.com/docs/devices/tv)。天气免费 API 当前仍限非商业用途；项目 MIT 与服务访问条件是不同事项。[Open-Meteo 条款](https://open-meteo.com/en/terms)。

**2026-10-14 所有者反馈后的通用修复（0.13.2-test）**

- 标准输入按公开父子关系合并 HDMI 端口和逻辑设备，多个设备保留选择菜单；父入口缺失、循环关系或类型不符时保留独立入口，不加入型号/端口 ID 猜测。单个子设备的名称显示在父卡片状态里，自定义端口名称保留。
- 默认顺序按原始系统 HDMI 标签中的数字排序；不把硬件/CEC ID 或自定义“输入源 5”当物理端口号。原有手动顺序、收藏、隐藏、分类及焦点引用随已知关系迁移，未知和暂时缺失键保留。
- 区分标准连接、待机、断开和未提供状态；读取标签或状态失败时保留已校验的播放入口。厂商返回非 Boolean 的插入状态保持未知，不伪报断开。TCL 元数据适配仍独立，不成为其他品牌默认端口表。
- 应用管理页显示标准会话的当前状态，把允许采集与实际公开接口分开。Android 8+ 运行时注册已有渠道历史广播，Activity/系统绑定媒体服务共享生命周期；定向广播仍走 manifest，保持原校验与无后台保活约束。每应用开关也约束旧 B 站渠道记录，不删除历史。
- 证据：所有者当前 Android 12/API 31 电视的授权截图与只读输入登记确认重复/待机映射问题；B 站 1.7.7 无记录、Netflix/YouTube 有记录来自所有者反馈。修复后的实机行为、B 站是否发送接口及背景导入均待验收，其他品牌未实测。设备截图留在忽略的本地目录，没有加入公开文档。
