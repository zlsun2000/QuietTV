# 借助 AI 定制静幕

本页面向准备修改源码的人和 AI。只想安装使用，请看 [使用指南](INSTALL.md)。

可复制的[安装与改造 Prompt](../README.md#把这段话交给-ai)在 README；只做媒体应用续播适配时，优先使用独立的 [RULE-PROMPT.md](../RULE-PROMPT.md)。

先按 [构建说明](BUILD.md) 完成一次未经修改的构建和核心检查，再逐项定制。将 [写作约定](WRITING.md)与本页提供给 AI；后续说明和汇报也要让不懂编程的人看得懂。这些文档不会自动验证 AI 生成的 APK。

## 从参数开始

修改 `res/raw/ui_defaults.properties`，重新构建即可。坐标以 1280×720 设计单位表达，最终依据实际应用窗口缩放，而非电视宣传的面板分辨率。

| 参数 | 默认 | 允许范围 | 作用 |
| --- | --- | --- | --- |
| `grid.columns` | 5 | 整数 4–6 | 全部应用及普通分类每行卡片数 |
| `clock.size` | 54 | 整数 40–60 | 时间字号 |
| `brand.size` | 18 | 整数 16–22 | 静幕品牌字号 |
| `weather.width` | 205 | 整数 160–250 | 顶部紧凑天气的宽度 |
| `favorites.ratio` | 0.60 | 0.55–0.65 | 有最近记录时左侧常用应用分区比例 |

非法数值回退已验证默认值。这里不覆盖全部 UI；颜色、位置和其他卡片参数仍需有针对性地改界面代码。首次定制可以用下面的任务：

> 阅读 docs/WRITING.md 和 docs/CUSTOMIZATION.md。把应用网格改为每行 4 个，时钟改为 48。只改已有配置参数，保留整行裁切和遥控器导航。构建 APK、运行核心检查，列出改动和仍需实机验证的项目；不要连接或操作我的电视。

## 修改布局

> 常用应用保持在左，继续播放保持在右。天气维持紧凑。先检查 MainActivity 的 PaneStrip、CardScroll、focusRows 和 visibilityBand。改动后测试多条记录左右滚动、边缘箭头、下一行完整进入视野和返回后的焦点。权限、包名及系统状态保持原行为。

布局不能用设备型号或固定 3840×2160 替代窗口测量。保留遥控器全部可达、稳定焦点、不显示下一行细缝、卡片不挤入另一分区等约束。

## 添加设备适配

> 为我的电视添加设置/输入源适配。先只读查询现有公开入口与设备报告，不猜 HDMI 数量。把设备专属规则放在 DevicePolicy/InputSources/SystemEntrypoints，不散落到 UI。接口不存在时隐藏增强功能并提供已有系统入口。明确测试证据，不能停用原厂应用、修改系统属性或开机流程。

对新增媒体应用，先验证标准 MediaSession 能公开什么，再决定是否需要专用适配；播放进度和内容入口分开验收，参考 [架构](ARCHITECTURE.md)。

0.14.0 起，已有广播/媒体会话/Watch Next 接入范围内的字段及续播差异可制作为独立 JSON 规则，无需改 APK。参见[规则规范、Schema、模板和 AI 提示词](PLAYBACK-RULES.md)。导入后主动启用并验证；没有接口时不能靠配置生成记录。

## 自己的签名与包名

如果只在自己的设备更新自建版本，用自己的固定密钥。想同时保留官方版，应选择新的包名，例如 `org.example.mytv`，并调整以下关联：

1. Java 包声明与 src 目录、manifest package、生成 R 类导入。
2. CHANGED 等私有广播 action，以及包名相关的固定组件。
3. 安装/恢复/测试脚本与文档里的启动组件。
4. 媒体会话、content provider 所属应用验证与对应测试；不能删除身份验证。

这是涉及多处关联的改动，当前没有承诺一键改包名。请让 AI 全仓检索 `local.quiettv` 后逐项修改，构建并验证全新安装；不要把自己的分支发布成官方 QuietTV APK。
