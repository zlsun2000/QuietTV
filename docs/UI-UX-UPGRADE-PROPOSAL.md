# 静幕 UI / UX 升级方案（待确认）

调研日期：2026-11-10。本文是任务二的提案，尚未实施；方案确认前不改 UI。Issue #5 的布局开关与性能排查是独立任务，不计入本方案工时。这里根据项目公开发布说明、问题和现有静幕源码做方案推导；没有安装或实机操作这些参考应用，不能把发布说明当作我们对其实际体验的验证。

## 目标与边界

保持深色、简洁、无广告，把跨应用「继续播放」放在容易理解的位置；视觉变化只服务于找到内容、判断能否续播、遥控器操作和减少误操作。保留现有壁纸、整行裁切、焦点恢复、设置和用户配置；兼容 TCL Android 9 与 Google TV Streamer，不 root、不修改原厂桌面，保留 `isLowRamDevice` 路径。播放规则系统、包名/版本/签名校验和续播路由保持原样；UI 只能展示已有记录与真实能力，不能猜测精确续播或增加数据来源。只参考交互思想，独立实现，不复制代码或素材。

## 建议范围与估算

估算为一名熟悉现有 Java / Android TV 代码的开发者的有效工作日（1 日约 8 小时），包括实现、必要自动检查和可用设备回归，不包括等待硬件、外部测试和发布；顺序与工作量待确认。以下不是对性能提升的承诺，先测量再定具体参数。

| 优先级 / 借鉴点 | 拟议设计与收益 | 成本 | 风险及控制 |
| --- | --- | --- | --- |
| P1 续播卡片信息层级（LtvLauncher、Jellyfin） | 保留现有行与内容来源；让标题、来源、已有进度和实际可执行动作清晰区分。无海报用稳定的本地占位；长标题省略并在焦点说明中提供完整名称。能更快辨认内容，避免把「打开应用」误认为精确续播。 | 2–3 日 | 过度叠字会遮盖海报或使小屏难读；使用现有数据，不新增网络封面或改变记录/规则；实测长中英文、无图、无进度和不同能力。 |
| P1 焦点与行导航一致性（LtvLauncher、Jellyfin） | 统一应用、续播、设置的焦点轮廓和可读对比度；保留遥控器返回位置、左右边界提示与整行裁切。根据 Issue #5 的实测结果选择动画，低内存路径使用经验证的简化表现。收益是可预期导航和更明确的当前选择。 | 2–3 日 | 阴影、放大、动画可能增加掉帧；不先假定原因或统一移除。按测量对比，验证大字号、壁纸和首末项焦点；不改变 `RowViewport` 约束。 |
| P1 整理操作更可发现（Aerial、LtvLauncher、SmartTube） | 在既有长按菜单和分类设置上补充简短操作提示；移动/隐藏后焦点停在可预测位置，必要时显示可撤销提示。减少进入多层菜单和误操作。Issue #5 的布局排序由独立任务负责。 | 2–3 日 | 提示过多造成干扰，撤销必须准确处理数据；只在相关上下文显示，先限定单步可逆操作并保留已存顺序。 |
| P2 设置说明与空状态（Jellyfin） | 沿用现有五组和逐级返回；对无收藏、无续播、权限未启用及无记录分别提供简洁原因与可达的下一步，非错误状态不显示失败。降低新用户无内容时的困惑。 | 2–3 日 | 不能把「无记录」误说成权限问题，也不能替用户启用权限；文案按已有可观测状态区分，未知状态明确说未知；焦点可返回。 |
| P2 背景下的可读性（Aerial） | 保留现有图片、视频、主题与生命周期；仅在必要区域使用轻量、固定的暗化/渐变，优先保障文字和焦点识别。收益是浅色背景下可读性更稳定。 | 1–2 日 | 遮挡用户壁纸、增加合成开销；不对每帧取样或实时模糊，低内存设备继续限制解码与视频策略，以浅/深背景检查。 |
| P3 本地应用搜索（lightweight launcher，SmartTube 返回经验） | 先在「整理应用」中增加可选本地名称筛选，不搜索网络或历史；退出详情/操作后保留查询及焦点，空结果提供清除筛选。大型应用列表更易整理。 | 2–4 日 | 遥控输入成本和中文输入法兼容；不默认占用主页空间，不引入语音或外部服务；检查键盘返回和焦点恢复。 |

P1 合计约 6–9 人日；P1+P2 约 9–14 人日；全部约 11–18 人日。交互评审、设备可用性及性能问题可能调整估算。建议先确认 P1+P2；P3 需要确认是否值得增加输入交互，再单独排期。

## 暂不建议借鉴

- 自动预览视频、动态模糊、大面积玻璃和多层阴影：额外解码或合成成本不一定换来更快找到内容，低内存设备风险较高。
- 在线推荐、在线壁纸、强制账户、自动播放或广告位：偏离本地、安静的桌面定位，也会扩大网络和隐私范围。
- 停止/禁用原厂桌面、root、强制重映射 Home、未经用户选择授予权限：违反兼容与设备边界。
- 大量主题/卡片尺寸开关、无明确需求的全局搜索、全量重写为新 UI 框架：增加设置与回归负担；现有原生构建及设备路径继续保留。
- 为外观填充或推断续播状态、联网补全封面、改变规则匹配或播放行为：损害已有续播真实性和安全边界。

## 确认后实施与验收

1. 对确认项先截取现有界面基线，列明可测目标；只改确认范围，和任务一分开提交。
2. 编译与核心检查单独记录；在隔离的 API 34 TV 模拟器分别检查全新安装、旧版升级及低内存路径。覆盖默认并排、分行、隐藏常用、空/多项、长标题、无图、输入源、按住方向键、行首行尾、设置往返和背景恢复。
3. 性能用相同内容、同设备、相同遥控输入录制前后帧耗时/卡顿和内存；以 Issue #5 排查结果为基线，不承诺模拟器数据代表真实硬件。
4. TCL Android 9 与 Google TV Streamer 分别实机检查遥控可达、焦点恢复、文字可读和续播动作；没有设备时明确标为未验证，并邀请测试者提供型号/系统和结果，不把编译或模拟器通过称为真机通过。
5. 验证老用户收藏、分类、壁纸、播放记录与权限选择不被重置，续播规则及验证链不变；保留无动画或低开销退路。
